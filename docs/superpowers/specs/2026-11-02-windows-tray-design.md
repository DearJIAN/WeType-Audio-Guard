# Windows 托盘阶段二设计

日期：2026-11-02。基线：main / 304856032a83a6e03371ccbd23b3c39eeecf0c5e。

## 目标与边界

在 Windows 10/11、PowerShell 7、Python 3.12.11 环境，为已实测成功的防静音原型增加轻量系统托盘。默认暂停，明确启用才允许恢复播放静音。不开发 EXE、开机自启、服务、注册表自启、自动更新、遥测或复杂 GUI。不自动进行真实音频保护联调，不修改麦克风、通信设置或音量数值。

## 方案选择

采用独立入口 `wetype_audio_tray.py`，原 `wetype_audio_guard.py` 保持字节不变，导入复用 `GuardPolicy`、`WindowsAudio`。托盘使用 pystray / Pillow，音频由唯一工作线程处理。

把托盘嵌入原 CLI 会扩大稳定基线变更面；另写保护算法会破坏复用要求；多个启停线程容易重入。因此独立入口和一个长期工作线程是符合本任务约束的方案。这里的实现细节为开发者建议，等待用户确认。

## 组件与文件

- `wetype_audio_tray.py`：Windows 入口、单实例锁、日志、菜单与图标更新、启动与退出编排。
- `tray_runtime.py`：线程安全状态与工作线程；通过可注入音频工厂和时钟支持模拟测试。
- `tray_icon.py`：Pillow 原创透明小鲸鱼；无外部素材，支持 16、24、32 像素。
- `tests/`：unittest 模拟音频、COM 生命周期、并发、错误与退出、单实例及图标测试。
- `requirements-tray.txt`：引用原 requirements.txt，附加 pystray 与 Pillow，CLI 依赖文件不变。
- README：区分 main 的已实测 CLI 与 feat/windows-tray 的待桌面验收托盘，说明运行、日志与限制。
- `docs/windows-tray-validation.md`：自动测试结果及用户桌面验收步骤。

## 状态与操作

默认保护暂停；显示保护状态、录音状态（未知/空闲/录音）、成功恢复次数及错误状态。菜单提供启用、暂停、不可点击的状态与计数、退出。无持久化自动启用；每次启动都暂停。

暂停状态不进行恢复；可继续只读监测录音状态。状态与计数是无 COM 引用的快照。蓝鲸表示启用，灰鲸表示暂停，异常附小型警示；录音由菜单和悬浮标题明确显示。

每次启用、暂停或错误都增加状态代数，旧轮询结果失效。读取结果提交和 SetMute 前检查代数与启用标记；同一短临界区串行化暂停与恢复。暂停操作确认返回后不得开始新恢复调用；已进入系统调用的操作不能撤回。UI 不持锁等待音频枚举，避免设备异常阻塞菜单。

## 音频与 COM

音频工作线程内 CoInitialize，创建和使用 WindowsAudio，退出前释放 COM 引用并 CoUninitialize；不跨线程传递接口，不在 UI 线程枚举设备。

复用原策略：录音进程 wetype_update.exe；默认 0.2 秒轮询和 2 秒窗口；空闲至少 3 次轮询建立基线。仅恢复基线未静音而后静音的已存在设备/会话；每周期每对象最多尝试一次，失败也不重试。录音期间启用或发生异常，必须等录音结束和新的空闲基线才保护，不用当前录音状态建立基线。

暂停/重新启用/枚举异常：丢弃策略和旧音频对象，下次重新初始化连接；异常期间不恢复。发现设备集合变化或部分枚举失败，同样失效本轮与基线，重新等待稳定空闲状态。原 WindowsAudio 会将单会话枚举异常打印到 stderr 后跳过：托盘适配层必须捕获这些警告并把该轮视为不完整快照，不改原 CLI 行为。

成功 SetMute(0, None) 才增加恢复次数。只修改输出静音布尔值，不设置音量，不恢复麦克风，不在退出时回滚静音。

## 单实例与退出

用 Windows Local 命名互斥体阻止同一登录会话的第二个托盘实例；名称结合当前用户 SID，避免同会话不同身份互相阻挡。检查 ERROR_ALREADY_EXISTS，明确提示后退出，句柄在生命周期末关闭。不要终止其他 Python 或 CLI 进程；文档提醒用户不要同时运行 CLI --protect。

只创建一个音频工作线程，多次启用/暂停不创建线程。退出先禁止写入、设置停止事件，使用 Event.wait 代替不可打断 sleep，等待线程结束并释放 COM、互斥体、日志，然后关闭托盘。普通设备失败应重试且可中断；未知的系统 COM 调用可能无法由 Python 安全取消：不能虚报已退出或用强杀其他进程掩盖问题。若实测存在无限阻塞，停止验收并将音频隔离到可终止的专用子进程作为后续设计修正，不带风险合并。

## 日志和隐私

标准 logging RotatingFileHandler，用户本地应用数据目录 WeTypeAudioGuard/logs，单文件 1 MiB，保留 3 个历史文件。记录启动退出、启用暂停、录音状态变化、恢复成功与失败、设备错误；连续同类错误限频。不记录语音、会议内容、PID、设备标识、完整路径或音频会话唯一标识；应用恢复日志最多保留进程名。日志仅本地，无网络上传，仓库忽略日志。

## 小鲸鱼

Pillow 绘制深海蓝圆润主体、海蓝肚腹/鳍、简化尾巴和眼睛，透明背景。高分辨率绘制后抗锯齿缩放，状态图分别检查 16/24/32 像素；暂停采用灰色，错误使用少量暖色警示。生成独立预览供审阅，不使用私人素材或第三方图标。

## 自动验证与验收

先运行原 py_compile 与 --self-test。unittest 全用模拟接口验证默认暂停、启用暂停、重复切换单线程、暂停与进行中的轮询竞态、录音中启用不恢复、异常清空基线、重连后重建基线、预静音/新会话/窗口外/重复恢复不触发、恢复失败不重试、设备变化、COM 初始化释放配对、退出线程清理、单实例重复启动及释放后重启。Windows 单实例测试使用独立测试名称和子进程，不锁实际应用；不触碰音频硬件。图标检查透明度、尺寸和人工预览。日志检查滚动上限及敏感字段排除。

允许只读启动/退出的桌面烟雾测试，但不自动启用保护；运行前说明操作范围。真实播放恢复、设备插拔、托盘菜单与显示缩放由用户在非正式会议环境验收，结果未确认前不得称为真实联调成功。
